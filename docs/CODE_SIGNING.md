# Подпись кода и SmartScreen

## Почему появляется «Система Windows защитила ваш компьютер»

Браузер помечает скачанный файл как «из интернета». При запуске такого файла SmartScreen
проверяет две вещи: подписан ли он и есть ли у подписи (или у самого файла) репутация.

* Неподписанный `Shotly.exe` — «Издатель: неизвестный издатель». Репутация копится для каждого
  файла отдельно, а CI выпускает новый exe при каждом мерже, так что она обнуляется каждый раз.
  Предупреждение не уйдёт никогда.
* Подписанный exe — в окне виден издатель, а репутация копится на сертификат и переходит на
  все следующие версии. Пока её мало, окно ещё может появляться; после нескольких сотен
  скачиваний без жалоб оно исчезает.
* С марта 2024 года EV-сертификат больше не снимает предупреждение сразу: он копит репутацию
  так же, как обычный. Платить за EV ради SmartScreen больше нет смысла.

Обновление внутри программы скачивает exe без пометки «из интернета», поэтому SmartScreen
мешает только при первом скачивании с сайта.

## Варианты

| Вариант | Цена | Кто указан издателем | Условия |
|---|---|---|---|
| **Azure Artifact Signing** (бывш. Trusted Signing) | 9,99 $/мес | Имя владельца после проверки документов | Частные лица — только США и Канада; организации — США, Канада, ЕС, Великобритания |
| **SignPath Foundation** | Бесплатно | «SignPath Foundation» | Открытый исходный код (MIT подходит), сборка в CI из открытого репозитория, ручное одобрение каждого релиза, страница «Code signing policy» |
| OV-сертификат (Certum, Sectigo и др.) | ~30–400 $/год + токен | Имя владельца | Ключ только на токене или в облаке CA (с 2023), неудобно в CI; многие CA не работают с некоторыми странами |
| Microsoft Store (MSIX) | Бесплатно для частных лиц | Microsoft подписывает сама | Отдельная упаковка MSIX и проверка магазина; не убирает предупреждение для exe с GitHub |

## Как включить в CI

Шаги уже есть в `.github/workflows/build.yml`. Они ничего не делают, пока не заданы
переменные репозитория, и подписывают только сборки из `main`. После подписи шаг
«Check signature» проверяет, что подпись действительна, иначе релиз не публикуется.

### Azure Artifact Signing

1. Завести подписку Azure, создать ресурс **Artifact Signing account**.
2. Пройти проверку личности (**Identity validation → Individual**), дождаться одобрения.
3. Создать **Certificate profile** типа *Public Trust*.
4. Создать App Registration, выдать ей роль **Artifact Signing Certificate Profile Signer**
   на аккаунт подписи, создать client secret.
5. В GitHub → Settings → Secrets and variables → Actions:
   * секреты `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`;
   * переменные `AZURE_SIGNING_ENDPOINT` (например `https://weu.codesigning.azure.net/`),
     `AZURE_SIGNING_ACCOUNT`, `AZURE_CERTIFICATE_PROFILE`.

### SignPath Foundation

1. Сделать репозиторий Shotly открытым.
2. Подать заявку на https://signpath.org/apply и дождаться одобрения.
3. В SignPath: подключить GitHub-коннектор, создать проект `shotly`, политику `release-signing`,
   конфигурацию артефакта для одного `Shotly.exe`.
4. Добавить в README раздел «Code signing policy» (текст даёт SignPath).
5. В GitHub: секрет `SIGNPATH_API_TOKEN`, переменная `SIGNPATH_ORGANIZATION_ID`
   (и при других именах — `SIGNPATH_PROJECT_SLUG`, `SIGNPATH_POLICY_SLUG`).

Каждый релиз ждёт ручного одобрения в SignPath (до часа, потом сборка падает).
